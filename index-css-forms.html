Form foundations

Good form design begins with structure

CSS makes a form attractive, but correct HTML makes it usable. Every control needs a clear purpose, a programmatically connected label, and feedback that is not communicated by color alone.

1

Use real labels

Connect <label for> to the control’s matching id.

2

Group related choices

Use <fieldset> and <legend> for radio and checkbox groups.

3

Keep focus visible

Keyboard users must always see which input or button is active.

Design rule: A placeholder is an example or hint—not a replacement for a visible label. Placeholder text disappears as soon as the user starts typing.
Correct label and input connection
HTML 
<label for="email">Email address</label>
<input
  id="email"
  name="email"
  type="email"
  autocomplete="email"
  required
>

Inputs, labels, textarea

Build a reusable field style

Style text-like controls consistently: full width, comfortable height, readable padding, a clear border, and a visible focus indicator.

Text input and textarea
HTML + CSS

  <label for="full-name">Full name</label>
  <input
    class="form-control"
    id="full-name"
    type="text"
    placeholder="Jane Smith"
  >
</div>

  min-height: 46px;

Action design

Style buttons for every interaction state

A button should look clickable, respond to hover and press, show keyboard focus, and clearly communicate when it is disabled.

Primary form button
CSS 
.submit-button {
  min-height: 46px;
  border: 0;
  border-radius: 10px;
  background: linear-gradient(
    120deg,
    #39e7ff,
    #7282ff
  );
  cursor: pointer;
  font-weight: 900;
  transition:
    transform 180ms ease,
    box-shadow 180ms ease;
}

.submit-button:hover {
  transform: translateY(-2px);
}

.submit-button:active {
  transform: translateY(1px);
}

.submit-button:disabled {
  cursor: not-allowed;
  opacity: 0.55;
}
Live states
⚙
Always set button type Inside a form, <button> defaults to submission. Use type="button" for actions that should not submit.

Checkboxes and radio buttons

Design custom choices without losing semantics

Checkboxes allow multiple selections. Radio buttons allow one selection from a named group. Keep the native input in the document and style it with appearance: none.

Custom checkbox and radio controls
CSS 
.choice input {
  width: 20px;
  height: 20px;
  border: 1px solid #53647e;
  background: #080d14;
  appearance: none;
}

.choice input[type="checkbox"] {
  border-radius: 6px;
}

.choice input[type="radio"] {
  border-radius: 50%;
}

.choice input:checked {
  border-color: #39e7ff;
  background: #39e7ff;
}

Select boxes

Style a select while keeping native behavior

Remove the default arrow with appearance: none, place the select inside a wrapper, and create a decorative arrow on the wrapper.

Custom select box
HTML + CSS 
<div class="select-wrap">
  <select class="select-control">
    <option>Choose a subject</option>
    <option>Support</option>
    <option>Sales</option>
  </select>
</div>

.select-wrap {
  position: relative;
}

.select-control {
  width: 100%;
  appearance: none;
  padding-right: 42px;
}

.select-wrap::after {
  content: "⌄";
  position: absolute;
  right: 14px;
  top: 50%;
  pointer-events: none;
}

Hover and focus states

Show users what is happening

Interactive states are feedback. Hover confirms that a control can be used. Focus shows keyboard position. Valid and invalid states explain whether input meets the requirements.

Normal
:focus
:valid
:invalid
Reusable interaction states
CSS 
.form-control:hover {
  border-color: #52657f;
}

.form-control:focus {
  border-color: #39e7ff;
  outline: none;
  box-shadow:
    0 0 0 3px rgb(57 231 255 / 11%);
}

.form-control:disabled {
  cursor: not-allowed;
  opacity: 0.55;
}
⌨
Do not remove focus without replacing it outline: none is acceptable only when you add an equally visible custom focus style.

Validation styling

Explain errors clearly and at the right time

Browsers provide :valid and :invalid. For a calmer experience, this lesson adds a .touched class after the user leaves a field and .was-validated after submit.

Interactive validation example
CSS 
.form-control.touched:invalid,
.form.was-validated
  .form-control:invalid {
  border-color: #ff6862;
  box-shadow:
    0 0 0 3px rgb(255 104 98 / 9%);
}

.form-control.touched:valid {
  border-color: #55e2a5;
}

.form-control:invalid
  + .error-message {
  display: block;
}

10

Form design mistakes

Avoid these common problems

1

Using placeholders instead of labels

Placeholders disappear and often use low contrast.

Always provide a visible <label>.
2

Removing focus outlines completely

Keyboard users lose track of their position.

Replace the outline with an equally visible focus ring.
3

Showing errors before the user interacts

A required empty form should not open as a wall of red fields.

Show errors after blur or submit.
4

Using color as the only error signal

Some users cannot distinguish red and green states.

Add descriptive text and appropriate ARIA connections.
5

Making controls too small

Small targets are difficult on touch screens and for users with motor limitations.

Aim for comfortable controls around 44px high.
6

Using vague button text

“Submit” says less than “Send message,” “Create account,” or “Save changes.”

Name the action clearly.

Practice and review

Test your understanding

Exercise 1: Connect a label to an email input.
<label for="email">Email</label> <input id="email" type="email">
Exercise 2: Style an input only while it has focus.
.form-control:focus { border-color: cyan; box-shadow: 0 0 0 3px rgb(0 255 255 / 12%); }
Exercise 3: Allow users to select exactly one contact method.
Use radio buttons with the same name value.
Exercise 4: Allow users to select several services.
Use checkboxes. Each checkbox may use the same name and a different value.
Exercise 5: Why should the select arrow ignore pointer events?
Because the decorative arrow sits over the select. pointer-events: none allows the click to reach the native select control.
Exercise 6: Show an error only after submit.
Add a class such as .was-validated to the form, then target .was-validated .form-control:invalid.
